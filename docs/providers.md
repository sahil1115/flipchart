# Provider integration

Verified documentation and public endpoint behavior: **9 October 2026**. Phase 4 status: **fixture-tested; live verification pending**. No real user API key was available or used. Alpha Vantage is implemented below in Phase 6, with live user-key verification pending.

## Twelve Data: sources and implementation choices

The [official documentation](https://twelvedata.com/docs) and [official machine-readable OpenAPI specification](https://api.twelvedata.com/doc/swagger/openapi.json) were reviewed for authentication, `/symbol_search`, `/api_usage`, `/time_series`, their parameters, response schemas and credit annotations. The specification was fetched directly from the provider. Relevant documented choices:

| Concern         | Verified contract and application behavior                                                                                                                                                                                                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Authentication  | The provider accepts `Authorization: apikey KEY`. FlipChart uses this header, never an `apikey` URL parameter. Browser developer tools can see authenticated requests; the application has no credential proxy.                                                                                                                |
| Search          | `/symbol_search`: symbol/company query, `outputsize` (maximum 120). FlipChart requests 30, waits 450 ms after typing at least two characters and cancels obsolete searches. Stock/ETF results retain exchange and MIC; missing search currency/timezone is labeled unavailable. Search does not establish subscription access. |
| Connection test | `/api_usage` reports `current_usage`, `plan_limit`, timestamp and optional plan category/daily limits. FlipChart reports the observed minute usage snapshot, never invents remaining credits or listing entitlements. The reviewed specification assigns **one credit** to this endpoint; testing is explicit.                 |
| History         | `/time_series`: `interval=1day`, `outputsize=5000` (documented endpoint maximum), `start_date`, `end_date`, `order=ASC`, JSON, and native MIC or exchange filter. The cap is an endpoint limit, not a promise that an account can access 5,000 bars.                                                                           |
| Adjustment      | `adjust=none` requests raw OHLC; `adjust=all` requests split/dividend-adjusted OHLC. The documented default is `splits`, which FlipChart overrides explicitly. Never splice adjusted close into raw open/high/low. Adjustment availability remains subject to account/market access.                                           |
| Dates           | Daily/weekly/monthly dates are exchange-local; the `timezone` parameter is ignored for these intervals. Preserve daily date strings and expose metadata currency/exchange timezone. Same exchange-date bars are conservatively provisional and excluded from finalized indicators.                                             |
| Access          | Capabilities advertise daily adapter support and documented adjustment request options, with access **unknown** and earliest history **unknown**. A successful usage test or search is not proof of history rights. Returned history must match symbol/MIC or exchange and supply valid currency/timezone.                     |
| Credits         | The reviewed specification annotates one credit for symbol search, usage test and time series per symbol. Each user action can make additional requests; no indicator endpoints are called. Browser preflight is transport overhead.                                                                                           |

Current [pricing](https://twelvedata.com/pricing), [credit guidance](https://support.twelvedata.com/en/articles/5615854-credits), [data add-ons](https://support.twelvedata.com/en/articles/10910460-data-add-ons), [exchange coverage](https://twelvedata.com/exchanges) and [historical-data guidance](https://support.twelvedata.com/en/articles/5214728-getting-historical-data) were checked. The pricing page advertised Basic at 8 API credits/minute and 800/day at verification. These numbers are **not hardcoded into the UI or treated as a universal entitlement**. Paid tiers, exchanges, add-ons, adjustments and history access vary. Account limits and current provider pricing prevail. Long requested windows can be truncated or refused; actual returned coverage and per-indicator insufficient-history states are always shown.

## Browser CORS evidence and limits

Public read-only probes used `Origin: http://127.0.0.1:5173` without a key:

- `GET /symbol_search?symbol=AAPL&outputsize=1`: HTTP 200, public Apple/NASDAQ search metadata, `Access-Control-Allow-Origin: *`, allowed headers including `Authorization`.
- `OPTIONS /time_series` with requested method GET and requested header Authorization: HTTP 204, wildcard allowed origin and Authorization permitted.

These probes support the direct browser/header design. **They do not verify authenticated history access or guarantee every endpoint/account/origin will succeed.** Production browser checks intercept all provider traffic with fixtures. Real-key browser history, production-origin CORS, market coverage, paid access and delay/EOD behavior remain pending. Network/CORS failures have a typed actionable state; there is no public proxy or automatic fallback to synthetic data.

## History, caching, freshness and errors

One normalized dataset feeds every calculation. A 1/3/5-year history request includes a calendar allowance for the largest current calculation requirement plus 300 observed bars of recursive warm-up. The allowance approximates observed sessions (7/5 calendar days plus 30 days); it is not an exchange calendar or a convergence guarantee. Actual coverage/count decides whether an indicator is available. Longer parameters update this allowance locally; only explicit **Load history** fetches more data. No pagination is needed within the single endpoint's 5,000-bar cap; longer unavailable history is disclosed rather than fabricated.

Query identity includes provider, random non-secret credential-session ID, reported plan when available, listing ID/symbol/exchange/MIC/currency/timezone, interval, requested boundaries, adjustment and current exchange date. Changing credentials clears the session cache. Identical in-flight requests deduplicate; matching loads reuse cache during the same exchange date. **Refresh loaded data** bypasses reuse for the loaded listing and convention, regardless of a pending selection. No automatic retries or focus/mount/reconnect fetches run. Theme, chart range/view, visibility and parameter edits make no provider requests.

Provider datasets remain in memory only: at most five query entries (including failures), 25,000 bars and an estimated 20 MiB of normalized serialized data, with 30-minute inactive query eviction. That timer is eviction, not a freshness timer. Memory cache has no raw response envelopes, request URLs or keys. No live response is written to IndexedDB, localStorage or service-worker storage. HTTP requests use `cache: no-store`, omit browser credentials/referrers and reject redirects. Provider response size is bounded at 5 MiB and 5,000 bars; normalization rejects non-finite prices, negative volume, conflicting duplicates, invalid dates/OHLC, mismatched listings and missing required metadata. Unknown volume remains null; real zero remains zero.

Typed errors cover missing/invalid key, quota, unsupported listing/interval/endpoint, insufficient history, empty, malformed, network/CORS, cancellation and outage. Both HTTP failures and error objects inside HTTP 200 JSON are recognized. Application errors use static messages and never reproduce provider text, URLs or credentials. Retry time is displayed only for a valid provider-supplied `Retry-After`; no reset countdown or remaining-credit estimate is invented. Obsolete responses cannot replace a newer selection even if transport ignores abort. Failed refresh keeps the previous chart, original fetch/data times and a visible stale warning. Delay/freshness is unknown unless supported by evidence; an accepted response is not automatically called real-time or EOD. Date-boundary stale evaluation occurs on rendering, with no background timer/fetch.

## Credentials, rights and attribution

The [terms](https://twelvedata.com/terms) (page dated 1 January 2026), [attribution guidance](https://support.twelvedata.com/en/articles/12647398-attribution-guidelines-for-using-twelve-data) and data add-on guidance were reviewed. Access, display, redistribution and permitted caching depend on the user's subscription/license. Application MIT licensing does not license the market data. The reviewed terms prohibit caching beyond permitted timeframes but do not establish a blanket retention duration suitable for all accounts. Therefore Phase 4 intentionally provides **session memory reuse only**, without promising universal data storage/display rights. Users must use their own account within its rights; public/shared display may require another license. Attribution links to Twelve Data whenever its dataset is active: **Data provided by Twelve Data**.

Keys default to memory. **Remember on this device** is unchecked initially and saves only on **Use key**, in a dedicated versioned `flipchart:credential:twelve-data` entry, separate from preferences and datasets. The UI explains that browser storage is not an OS credential vault. Reload can restore a remembered masked key but makes zero automatic requests. Unchecking Remember removes the saved credential immediately. Disconnect deletes the saved key, clears session identity/authenticated queries and the active live dataset while retaining the demo/import library. Clear Cache clears datasets and provider queries, retaining key/appearance preferences; Reset Preferences retains the key and datasets. Storage denial produces a warning and preserves memory use. Failed deletion is explicitly disclosed.

No real key is in source, tests, screenshots or documentation. Fixtures use an explicitly fake credential and fictional listings. CSV export is now implemented in Phase 6; no provider credential is part of the normalized dataset contract. Service-worker exclusion will be enforced in Phase 7; no service worker exists in Phase 4.

## Alpha Vantage - Phase 6

Reviewed official documentation, support, premium access and terms on **9 October 2026**:

- [API documentation](https://www.alphavantage.co/documentation/): raw `TIME_SERIES_DAILY` compact supplies the latest 100 points; full daily history requires premium. Native `TIME_SERIES_WEEKLY` and `TIME_SERIES_MONTHLY` provide raw OHLCV with last-trading-day labels and documented long history. Their sections link free keys; no account entitlement is inferred. The daily adjusted endpoint is premium and supplies adjusted close alongside raw OHLC; FlipChart excludes it entirely. Returned coverage governs availability.

- [Support](https://www.alphavantage.co/support/) and [premium access](https://www.alphavantage.co/premium/): standard free access is advertised as 25 requests/day. Verified open-source/educational exceptions require provider approval; FlipChart does not assume this exception. No local remaining-credit counter or retry countdown is invented.

- [Terms of service](https://www.alphavantage.co/terms_of_service/): the default license is personal/noncommercial; broader commercial use needs a written agreement. The grant is nontransferable and nonsublicensable. Implementation decision: private browser use, no shared key/feed, no durable provider cache; export describes the user's permitted use rather than granting redistribution. Account/exchange conditions still apply.

The adapter sends only search and raw history requests to the fixed official HTTPS endpoint. `apikey` is required in the query; browser developer tools can see it. Safe typed errors never reflect provider messages or transport URLs. Query identity includes provider, session/access, native listing, interval, boundaries, adjustment and compact/full choice. Connection testing uses an explicit IBM search request; usage/limit/plan stay unavailable. Search offset strings are not treated as IANA zones; history supplies the timezone. Region is retained separately from unavailable exchange/MIC. Native symbols/suffixes come from this provider's search, never blindly converted from another provider.

Requests exclude cookies/referrer, bypass HTTP caching, reject redirects and time out after 20 seconds. Responses are bounded to 5 MiB and 10,000 bars, validated before range slicing. Null volume remains unknown. Daily current-day and native current-week/month bars are conservatively provisional. No pagination or premium upgrade is automatic. Native weekly/monthly input cannot be transformed into daily input; load another native interval explicitly. Calendar boundaries use the returned exchange timezone; unknown timezone search requests use a UTC date boundary until history supplies one.
